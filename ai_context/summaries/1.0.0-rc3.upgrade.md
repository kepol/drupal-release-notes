Test the update on a copy of the site first.

#### Update the code

- CCC now requires drupal/ai 1.4.12 or later on the 1.4 branch, or 1.5.2 or later (`~1.4.12 || ^1.5.2 || ^2`). If your site uses AI 1.4.11 or earlier, update AI together with CCC: `composer update drupal/ai_context drupal/ai -W`. To stay on AI 1.4, add `--with drupal/ai:~1.4.12`. All supported AI versions send the automator ID tag and the entity context that the Automator consumer type needs, so the rc2 limits for Automators on AI 1.4.x no longer apply (#3586724).
- Run `drush updatedb`, then `drush cr`.
  - Update 10033 adds the storage of the new **Token name** field. Existing items get no token name (#3586760).
  - Post-update 0017 replaces the two CCC Scheduler permissions with Scheduler's permission (see "Check permissions") (#3586711).
  - Post-update 0008 now ignores include-list values that are not a numeric item ID or a valid UUID. This is important only for sites that have not run post-update 0008 yet (#3586749).
  - `drush cr` is needed because selection results now depend on the `language.negotiation` configuration, the context item form changed, the `ai_context.scheduler_defaults` service has new arguments, and there are new token hooks, a new item delete form and a new translation delete form (#3586746, #3586721, #3586711, #3586760).

#### Check permissions

- The CCC permissions **Schedule publishing of AI Context Items** and **View scheduled AI Context Item** are removed. No code checked them. When Scheduler is installed, post-update 0017 gives Scheduler's **Schedule publishing and unpublishing of AI Context Item** to each role that had one of the old permissions, and its message names the roles that it changed. When Scheduler is not installed, give Scheduler's permission yourself after you install Scheduler (#3586711).
- A role that sets dates also needs the workflow transition that the date starts: **AI Context editorial workflow: Use Publish transition** for "Publish on" from Draft or Published, **AI Context editorial workflow: Use Restore transition** for "Publish on" from Archived, and **AI Context editorial workflow: Use Archive transition** for "Unpublish on". An Archived item also needs **AI Context editorial workflow: Use Restore transition** for "Unpublish on" (#3586711).
- After `drush updatedb`, run `drush config:export` and commit the result, because the update changes role configuration. If you import configuration that you exported before the update, the import puts the removed permissions back and removes the Scheduler permissions that the update gave. Do the export before you deploy with `drush deploy`, because `drush deploy` runs `drush updatedb` and then imports configuration. If a recipe, an install profile or a configuration export has the old permission names, change them to Scheduler's names (#3586711).
- Only users with **Administer AI Context** can set the new **Token name** (#3586760).

#### Check settings and content

- Multilingual sites that detect the language from a URL path prefix: a Site Section pattern without the prefix now matches the page in every language, so `/about/*` also matches `/af/about/team`. If an item must get to one language only, also add the Language scope to the item. A pattern that includes a prefix, such as `/af/about/*`, still matches, but only in that language (#3586746).
- On AI agents, the provider in **AI Provider/Model** on **General Settings** now receives the first 500 characters of the user request, not of the agent instructions, for conditional subcontext decisions. If you do not want this, turn off **Enable conditional subcontext AI decisions**, or use the same provider as your agents (#3586710).
- **Always include** and **Never include** now match a UUID only in the lower-case 8-4-4-4-12 form. An item whose stored UUID has another form, for example after a default_content or migrate import, is no longer matched by these lists. Add such items to the lists again by their numeric ID (#3586741).
- The fix for detached "Same as parent" subcontext items does not change items that were detached before this update. Look for translated items that have no scope and no parent, and unpublish the translations that must not get to all users (#3586742).
- Translators: these source strings changed or are new: the description of **Administer AI Context**, two Site Sections help texts about language prefixes, the message on the translation form that says that the fields that apply to all languages are hidden, and the **Token name** field, its help texts, and the token warnings and errors (#3586606, #3586746, #3586721, #3586760).

#### Changes that can affect integrations and custom code

- `AiContextSelection::getTask()` returns the user request on agent selections, or an empty string when the run has no user text. Subscribers of `ai_context.selection.items_selected` and `ai_context.selection.text_rendered` get this task. Code that uses the task as a search query must accept an empty task. See "Upgrade from 1.0.0-rc2: the agent selection task is the user request" in `docs/developers/api-stability.md` (#3586710).
- Selection results and the subscription budget calculation now have the cache tag `config:language.negotiation` (#3586746).
- The context item and usage list builders now set the empty text on `$build['table']['#empty']`, not on `$build['#empty']` (#3586692).
- The `ai_context.scheduler_defaults` service has two new optional arguments: the content moderation information service and the Scheduler manager (#3586711).
- Context items have a new base field `token_name` and the method `AiContextItem::getTokenName()`. CCC implements `hook_token_info()` and `hook_tokens()` for the `[ai_context:item:TOKEN_NAME]` token. The token neutralizer now also breaks an open `[` at the end of the pushed context block and of tool outputs (#3586760).

#### Known issues

- The **Content** editor on the context item form traps keyboard focus: in rich text mode, Tab and Shift+Tab do not move focus out of the editor. Press Escape and then Tab, or switch to Source mode. The fix is planned in the AI module (project/ai#3586814+s).
- On the context items list (`/admin/config/ai/context/items`), the filters apply only to the items on the current page. Matching items on other pages are not shown. Check each page of the list. The fix is planned for 1.0.1 (#3586567).
- On Drupal 10.5 and 11.2, AI CKEditor 1.4.3 and 1.4.4, and 1.5.0-beta1 to 1.5.0-beta5, stop the service container: `drush cr` fails with "Cannot autowire service ... AiCKEditorHooks". CCC does not cause this. Use Drupal 10.6 or later on the 10.x branch, or 11.3 or later on the 11.x branch. Use a release of AI CKEditor that addresses [SA-CONTRIB-2026-187](https://www.drupal.org/sa-contrib-2026-187) (project/ai_ckeditor#3615859+s).
- The Load tool (`ai_context:load_ai_context_items`) can return an item that an agent asks for by its ID regardless of the Roles scope, if its translation is published and the user has view access. Limit the Load tool to agents whose users should receive the context those agents can load. Roles is not an access boundary. The follow-up is planned for 1.1.0 (#3586707).
- After `drush updatedb`, export your configuration again before you import it. Do not import a sync directory that you exported from 1.0.0-beta4 or earlier. The fix is planned for 1.0.1 (#3586666).
- On a site that detects the language in another way than the URL prefix, for example from the domain, a page whose first path segment is the same as a language prefix can get the wrong translation of an item. The fix is planned for 1.0.1 (#3586763).
- On AI agents, when the run has no user text, conditional subcontext still makes one decision call for each conditional parent with an empty "Current task". The fix is planned for 1.1.0 (#3586636).
- The red status badges, for example **Disabled** and **Unpublished**, have low contrast in light mode (#3586662).
- Revision pages can show some data that the user cannot otherwise view, for a user who has **View all AI Context Item revisions** and can view the context item. Give this permission only to roles that can view all the content that context items refer to (#3586704).
- With the drupal/ai versions that CCC requires, scope pill tooltips and the Automator description tooltip show HTML entities such as `&amp;` (#3586705).
- An automator call that does not push context can send the context block of an earlier call on the same field, with a provider that sends the system role of the provider instance, for example an OpenAI-based provider. Workaround: make every call on the field push context, or turn off **Push context automatically** for the automator. The fix must be in AI Automators (project/ai#3586900+s).
- With Scheduler Content Moderation Integration, a user can save a context item with a schedule that starts a workflow transition that the user may not use, when the same save also changes the moderation state. Give Scheduler's **Schedule publishing and unpublishing of AI Context Item** only to roles that may use all transitions of the AI Context editorial workflow. The fix is planned for 1.0.1 (#3586720).
