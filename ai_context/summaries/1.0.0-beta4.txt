The 1.0.0-beta4 release of Context Control Center (CCC) gives site builders more control over which context items reach an AI agent and in what order. A new Priority field on context items influences selection ordering, the fixed maximum item limit was removed in favor of a token budget, and token counts are now stored per item and shown in the CCC UI together with a subscription-limit indicator so you can see how much of the budget a configuration uses. Scope plugins gained a multi-vocabulary Taxonomy Terms scope, optional icons for the UI, and renamed Entity Types and Specific Entities plugins with a clearer extension boundary for contributed plugins. Agents can now opt out of automatic context injection, a dedicated editorial workflow is available for context items, and the Document Loader context importer is promoted from experimental to stable. Conditional subcontext selection was tuned and tested, with new guidance for writing the Purpose field.

Stability and upgrade work is a major part of this release. Drupal 10 compatibility is restored, incomplete beta3 upgrades are repaired, and the beta2 upgrade path no longer fails after the bundleless entity conversion. Fixes also cover a white screen on some settings tabs, a Composer patch path that broke dependent project installs, missing field storage when Dynamic Entity Reference is enabled on an existing site, and provider configuration handling in conditional subcontext selection. Permissions were reviewed and a role and permission matrix documented, context item access checks were hardened alongside a written authoring trust model, and the overview page no longer loads the full published catalog. Help text and documentation now explain scope eligibility, ranking factors, and limits, and the test suite gained accessibility coverage, upgrade regression tests, and more robust functional tests. This release also reflects feedback from the beta tester community and a full QA pass.
