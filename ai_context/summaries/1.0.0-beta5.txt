The 1.0.0-beta5 release of Context Control Center (CCC) reworks how context items are selected and delivered. Selection modes are now a nested Minimal / Relevant / Broad ladder with a site-wide default that individual agents can override, and the Relevant mode uses a prefilter instead of scanning the full catalog. Scope plugins gained finer control: a new Roles scope limits context items to the acting user's roles, the Entity Types scope can match all bundles of a type, the Languages scope is treated as unavailable on single-language sites, and scope capabilities are now declared explicitly instead of through a single `supportsSubscriptions()` flag. Context consumers moved to a plugin-based architecture with unified configuration, including a new Automators consumer so the same context items can serve AI Automators as well as agents and the chatbot. A university sample set of context items and a recipe make it easier to try CCC on a fresh site.

This release also focuses on stability and upgrade safety. The context item scope storage was replaced with a multi-value scope ID plus value field, with update hooks that handle sites still on the older serialized format and clean up stale scope values when options are deleted. Fixes cover the beta4-to-beta5 upgrade and config-import path, a missing moderation_state field on recipe and config-sync installs, consumer include/exclude settings now stored as UUIDs instead of entity IDs, Site Sections matching on API proxy routes such as the chatbot endpoint, entity view access checks with correct cacheability, and a Drupal 10 fatal error from unregistered hook classes. Public selection APIs were renamed from Request to Selection terminology, listing pages are easier to scan, and documentation now covers RAG usage, real-world use cases, recipe and config-sync install requirements, and chatbot context delivery. The automated test suite was expanded significantly, including integration tests that use the EchoAI dummy provider, alongside a full QA pass by the QA team.
