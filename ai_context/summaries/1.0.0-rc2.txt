The 1.0.0-rc2 release of Context Control Center (CCC) is the second release candidate. It gives QA a fixed build to test the changes made after rc1, before the 1.0.0 release. Most of this release comes from a security and bug review of the code before 1.0. CCC now delivers only published translations of context items, filters subcontext children by view access and hard-filter scope, and reads the Entity Types bundle only from entities that the user can view. The core "view any unpublished content" permission no longer shows unpublished context items, Diff pages require the revision permission, Duplicate always saves the copy as a draft, and context items and usage records are no longer available through JSON:API. Drupal tokens in context item text are no longer replaced on any path, so item text cannot send user data to the AI provider. When scope cleanup removes the last value of a hard-filter scope, the item is unpublished, and the uninstall of Dynamic Entity Reference is blocked so that Specific Entities values are not deleted. CCC now requires drupal/ai 1.4.11 or later on 1.4, or 1.5.2 or later, because older versions show tooltip text as HTML.

New sites get a default token budget of 20,000 instead of 1,200. Existing sites keep their saved value. The stored token count of each item now includes its rendered header, so the Tokens column matches what the budget uses, and the truncation warning explains what it means. Usage records and invocation results count only the items that the budget delivered, "Last used" changes each time an item is used, usage records keep a limited number of request paths, and CCC uses approximate token counts when the tiktoken vocabulary cannot load. Other fixes keep consumer overrides during any module uninstall, resolve duplicate consumer IDs the same way everywhere, set the moderation state when Scheduler publishes on save, and vary Site Sections results by request path. Site builders can add CCC to the admin menu, the item and consumer listings now show published items and pushed consumers by default and have Reset buttons, and the scope settings table and status badges have accessibility fixes. For developers, the new load_ai_context_items function call replaces load_ai_context_item_by_id, which is deprecated and will be removed in 2.0.0. The entity_context keys are documented as public API, and the docs are updated for 1.0.0 with a new known issues page. This release also credits the work for the DrupalCon Rotterdam Inside AI demo, which configured CCC for AI Answers, Canvas AI, CKEditor and automator consumers. Run the database updates after you upgrade.
