Changes since 1.0.0-rc2 (compare)

1.0.0-rc3

37 credited issues

The 1.0.0-rc3 release of Context Control Center (CCC) is the third release candidate for 1.0.0, and the last one that is planned before 1.0.0. Most changes come from the rc2 smoke test and from the 1.0.0 bug review. Translators can no longer change the settings that all languages share, such as the scopes, from the translation form. A detached "Same as parent" subcontext item is now unpublished in every translation. Automator requests get one context block each. On AI agents, the selection task is now the user request, not the agent instructions. Site Section patterns now match pages that have a language URL prefix. Get Relevant, the consumer form and post-update 0008 no longer fail on an include-list value with a non-ASCII character, and Never include also removes an item that the tool input gives with leading zeros. CCC now uses Scheduler's own permissions for context items and rejects schedules that the workflow cannot run. This release also adds one new feature: an optional Token name for a context item, so that its text can be used as a Drupal token, for example [ai_context:item:brand_voice] in an AI agent system prompt. CCC now requires drupal/ai 1.4.12 or later on the 1.4 branch, or 1.5.2 or later. Read the upgrade notes before you update: you must run drush updatedb and then drush cr, and some changes need a check of your site.

Upgrade notes

Test the update on a copy of the site first.

Update the code

  • CCC now requires drupal/ai 1.4.12 or later on the 1.4 branch, or 1.5.2 or later (~1.4.12 || ^1.5.2 || ^2). If your site uses AI 1.4.11 or earlier, update AI together with CCC: composer update drupal/ai_context drupal/ai -W. To stay on AI 1.4, add --with drupal/ai:~1.4.12. All supported AI versions send the automator ID tag and the entity context that the Automator consumer type needs, so the rc2 limits for Automators on AI 1.4.x no longer apply (#3586724).
  • Run drush updatedb, then drush cr.
  • Update 10033 adds the storage of the new Token name field. Existing items get no token name (#3586760).
  • Post-update 0017 replaces the two CCC Scheduler permissions with Scheduler's permission (see "Check permissions") (#3586711).
  • Post-update 0008 now ignores include-list values that are not a numeric item ID or a valid UUID. This is important only for sites that have not run post-update 0008 yet (#3586749).
  • drush cr is needed because selection results now depend on the language.negotiation configuration, the context item form changed, the ai_context.scheduler_defaults service has new arguments, and there are new token hooks, a new item delete form and a new translation delete form (#3586746, #3586721, #3586711, #3586760).

Check permissions

  • The CCC permissions Schedule publishing of AI Context Items and View scheduled AI Context Item are removed. No code checked them. When Scheduler is installed, post-update 0017 gives Scheduler's Schedule publishing and unpublishing of AI Context Item to each role that had one of the old permissions, and its message names the roles that it changed. When Scheduler is not installed, give Scheduler's permission yourself after you install Scheduler (#3586711).
  • A role that sets dates also needs the workflow transition that the date starts: AI Context editorial workflow: Use Publish transition for "Publish on" from Draft or Published, AI Context editorial workflow: Use Restore transition for "Publish on" from Archived, and AI Context editorial workflow: Use Archive transition for "Unpublish on". An Archived item also needs AI Context editorial workflow: Use Restore transition for "Unpublish on" (#3586711).
  • After drush updatedb, run drush config:export and commit the result, because the update changes role configuration. If you import configuration that you exported before the update, the import puts the removed permissions back and removes the Scheduler permissions that the update gave. Do the export before you deploy with drush deploy, because drush deploy runs drush updatedb and then imports configuration. If a recipe, an install profile or a configuration export has the old permission names, change them to Scheduler's names (#3586711).
  • Only users with Administer AI Context can set the new Token name (#3586760).

Check settings and content

  • Multilingual sites that detect the language from a URL path prefix: a Site Section pattern without the prefix now matches the page in every language, so /about/* also matches /af/about/team. If an item must get to one language only, also add the Language scope to the item. A pattern that includes a prefix, such as /af/about/*, still matches, but only in that language (#3586746).
  • On AI agents, the provider in AI Provider/Model on General Settings now receives the first 500 characters of the user request, not of the agent instructions, for conditional subcontext decisions. If you do not want this, turn off Enable conditional subcontext AI decisions, or use the same provider as your agents (#3586710).
  • Always include and Never include now match a UUID only in the lower-case 8-4-4-4-12 form. An item whose stored UUID has another form, for example after a default_content or migrate import, is no longer matched by these lists. Add such items to the lists again by their numeric ID (#3586741).
  • The fix for detached "Same as parent" subcontext items does not change items that were detached before this update. Look for translated items that have no scope and no parent, and unpublish the translations that must not get to all users (#3586742).
  • Translators: these source strings changed or are new: the description of Administer AI Context, two Site Sections help texts about language prefixes, the message on the translation form that says that the fields that apply to all languages are hidden, and the Token name field, its help texts, and the token warnings and errors (#3586606, #3586746, #3586721, #3586760).

Changes that can affect integrations and custom code

  • AiContextSelection::getTask() returns the user request on agent selections, or an empty string when the run has no user text. Subscribers of ai_context.selection.items_selected and ai_context.selection.text_rendered get this task. Code that uses the task as a search query must accept an empty task. See "Upgrade from 1.0.0-rc2: the agent selection task is the user request" in docs/developers/api-stability.md (#3586710).
  • Selection results and the subscription budget calculation now have the cache tag config:language.negotiation (#3586746).
  • The context item and usage list builders now set the empty text on $build['table']['#empty'], not on $build['#empty'] (#3586692).
  • The ai_context.scheduler_defaults service has two new optional arguments: the content moderation information service and the Scheduler manager (#3586711).
  • Context items have a new base field token_name and the method AiContextItem::getTokenName(). CCC implements hook_token_info() and hook_tokens() for the [ai_context:item:TOKEN_NAME] token. The token neutralizer now also breaks an open [ at the end of the pushed context block and of tool outputs (#3586760).

Known issues

  • The Content editor on the context item form traps keyboard focus: in rich text mode, Tab and Shift+Tab do not move focus out of the editor. Press Escape and then Tab, or switch to Source mode. The fix is planned in the AI module (project/ai#3586814).
  • On the context items list (/admin/config/ai/context/items), the filters apply only to the items on the current page. Matching items on other pages are not shown. Check each page of the list. The fix is planned for 1.0.1 (#3586567).
  • On Drupal 10.5 and 11.2, AI CKEditor 1.4.3 and 1.4.4, and 1.5.0-beta1 to 1.5.0-beta5, stop the service container: drush cr fails with "Cannot autowire service ... AiCKEditorHooks". CCC does not cause this. Use Drupal 10.6 or later on the 10.x branch, or 11.3 or later on the 11.x branch. Use a release of AI CKEditor that addresses SA-CONTRIB-2026-187 (project/ai_ckeditor#3615859).
  • The Load tool (ai_context:load_ai_context_items) can return an item that an agent asks for by its ID regardless of the Roles scope, if its translation is published and the user has view access. Limit the Load tool to agents whose users should receive the context those agents can load. Roles is not an access boundary. The follow-up is planned for 1.1.0 (#3586707).
  • After drush updatedb, export your configuration again before you import it. Do not import a sync directory that you exported from 1.0.0-beta4 or earlier. The fix is planned for 1.0.1 (#3586666).
  • On a site that detects the language in another way than the URL prefix, for example from the domain, a page whose first path segment is the same as a language prefix can get the wrong translation of an item. The fix is planned for 1.0.1 (#3586763).
  • On AI agents, when the run has no user text, conditional subcontext still makes one decision call for each conditional parent with an empty "Current task". The fix is planned for 1.1.0 (#3586636).
  • The red status badges, for example Disabled and Unpublished, have low contrast in light mode (#3586662).
  • Revision pages can show some data that the user cannot otherwise view, for a user who has View all AI Context Item revisions and can view the context item. Give this permission only to roles that can view all the content that context items refer to (#3586704).
  • With the drupal/ai versions that CCC requires, scope pill tooltips and the Automator description tooltip show HTML entities such as &amp; (#3586705).
  • An automator call that does not push context can send the context block of an earlier call on the same field, with a provider that sends the system role of the provider instance, for example an OpenAI-based provider. Workaround: make every call on the field push context, or turn off Push context automatically for the automator. The fix must be in AI Automators (project/ai#3586900).
  • With Scheduler Content Moderation Integration, a user can save a context item with a schedule that starts a workflow transition that the user may not use, when the same save also changes the moderation state. Give Scheduler's Schedule publishing and unpublishing of AI Context Item only to roles that may use all transitions of the AI Context editorial workflow. The fix is planned for 1.0.1 (#3586720).

Release notes from merge requests

These notes come from the merge requests in this release. They describe what changed and what to do after you update.

Issue #3586606: Document which AI modules receive pushed context, and what external agents can and cannot do in 1.0.x.

Added documentation of which AI modules receive pushed context (Supported AI modules) and of what external agents can and cannot do with CCC in 1.0.x (Access boundaries, Outside the site). Corrected the Administer AI Context permission description: it also bypasses revision access checks.

Issue #3586658: Document how to test CCC with the AI Agents debugger and the Tools explorer.

None. Documentation only.

Issue #3586692: Context items listing does not show its empty text or the "Add one" link.

The empty context items listing now shows an "Add one" link for users who can create context items.

Issue #3586708: Leading-zero item IDs in tool input skip Never include.

Never include now also removes an item when the Always include or Never include list of the Get Relevant tool gives the item ID with leading zeros, for example "0123" for item 123. Before this change, the Get Relevant tool could deliver an item that the consumer has in Never include. The include lists still keep item IDs above 2147483647.

The Load tool now accepts only integers and strings of digits from 1 to 2147483647, with optional leading zeros and spaces. It ignores other values, such as "1e0", "1.0" or "+1", which loaded item 1 on MySQL and MariaDB before this change. No post-merge steps are necessary. There are no API changes: AiContextNumeric is @internal.

Issue #3586709: Automator context is added again for each field value, and is lost on AI 1.4.11 and earlier.

Automator requests now get one context block each. Before this change, each value of a multi-value base field added one more context block to the next request, on all supported AI versions. Known limit: when a later request of the same automator does not push context, OpenAI-based providers can still send the context block of the earlier request. This needs a fix in AI Automators. See "Known issues" in the CCC docs.

No post-merge steps. No API or hook changes.

Issue #3586710: On AI agents, conditional subcontext uses the agent instructions as the task, not the user request.

On AI agents, the selection task is now the user request. Before, it was the agent system prompt.

  • Behavior change: conditional subcontext decisions on agents now use the user question. AiContextSelection::getTask() returns the user request on agents, or an empty string when the run has no user text. Subscribers of ai_context.selection.items_selected and ai_context.selection.text_rendered get this task. Code that uses the task as a search query must accept an empty task.
  • Privacy change: the decision provider ("AI Provider/Model" in the CCC general settings) now receives the first 500 characters of the user request, not of the agent instructions. The generic chat path already does this. A site that does not want this can turn off "Enable conditional subcontext AI decisions", or use the same provider as its agents.
  • Known limit: when the run has no user text (in the chat input, the task description or the chat history), the task is empty, and conditional subcontext still makes one decision call for each conditional parent, with an empty "Current task". This is rare. #3586636 skips conditional decisions when the task is empty.
  • Known limit: CCC keeps the user request for each agent ID until the PHP process ends. If the same agent runs again in one process and its first loop is above 0, for example an agent that calls itself as a sub-agent, the later loops use the user request of the last run that started at loop 0.

Issue #3586711: Two CCC Scheduler permissions are never checked, and the item form saves schedules that cron cannot run.

The CCC permissions Schedule publishing of AI Context Items (schedule publishing of ai context items) and View scheduled AI Context Item (view scheduled ai context item) are removed. No code checked them. Scheduler checks only its own permissions for context items.

  • To let a role set "Publish on" and "Unpublish on" dates, give it Scheduler's Schedule publishing and unpublishing of AI Context Item (schedule publishing of ai_context_item). The role also needs the workflow transition that the date starts from the current state of the item: AI Context editorial workflow: Use Publish transition for "Publish on" from Draft or Published, AI Context editorial workflow: Use Restore transition for "Publish on" from Archived, and AI Context editorial workflow: Use Archive transition for "Unpublish on". An Archived item also needs AI Context editorial workflow: Use Restore transition for "Unpublish on".
  • Scheduler's View scheduled AI Context Item (view scheduled ai_context_item) has no effect on context items now, because context items have no list of scheduled items.
  • The update removes the old permissions from all roles. When Scheduler is installed, the update gives Scheduler's matching permission to each role that had an old one. Admin roles already have every permission, so the update only removes the old names from their stored configuration. When Scheduler is not installed, give Scheduler's permission yourself after you install Scheduler. The update message names the roles that it changed.
  • If a recipe, an install profile, or a configuration export has the old permission names, change them to Scheduler's names.

After drush updatedb, export your configuration and commit it. The update changes role configuration. If you import configuration that you exported before the update, the import puts the removed permissions back on the roles and removes the Scheduler permissions that the update gave. Core then removes the old names the next time someone saves the role, and logs "Non-existent permission(s) assigned to role". Do the export before you deploy with drush deploy, because it runs drush updatedb and then imports configuration.

The context item form now shows an error on "Publish on" or "Unpublish on" when the workflow cannot run the scheduled date. Content Moderation's "Change to" form on the item page shows an error when the new state makes the schedule unable to run.

Issue #3586721: Translators can change the shared scopes of a context item from the translation form.

The translation form of a context item no longer shows the settings that apply to all languages: the Context Scope settings, Priority, Specific Entities, Same as parent and the empty Subcontext settings box. Before this change, a user who could translate an item but not edit it could change these settings for all languages, for example remove a Roles scope or mark the item global. The save worked only for items outside the editorial workflow; for items in the workflow, Drupal core refused it. For items in the editorial workflow, the shared settings are now also hidden on the item's own edit form in another language, for example /af/admin/config/ai/context/items/[id]/edit. Edit the shared settings on the item's edit form in the original language. For items outside the workflow, users who can edit context items can still change them while they add or edit a translation, as in core.

This also fixes translations of subcontext child items. Before this change, a translator could not save the translation of a child item, and editors could not save it for items in the editorial workflow. The save failed with "Subcontext type is required when a parent context is selected." No post-merge steps. No API or hook changes.

Issue #3586723: Add a Release notes section to the merge request template and update the checklist.

None. This change affects only the merge request template for CCC contributors. Sites see no change.

Issue #3586724: Require AI 1.4.12, or document the lost generic-path context on AI 1.4.11.

CCC now requires AI 1.4.12 or later on the 1.4 branch, or AI 1.5.2 or later (~1.4.12 || ^1.5.2 || ^2). On AI 1.4.11 and earlier, context that CCC pushed into automator requests and other generic chat requests did not reach OpenAI-based providers, although the debug log and the Usage tab reported the push. Sites on AI 1.4.11 or earlier must update AI before they update CCC.

No other post-merge steps. No API or hook changes.

Issue #3586741: Get Relevant fails with a database error when an include list has a non-ASCII value (MariaDB and MySQL).

The Get Relevant tool, stored consumer include lists, the consumer settings form and post-update 0008 now ignore an include-list value that is not a numeric context item ID or a lower-case UUID. Before this change, on MariaDB and MySQL, a value with a non-ASCII character (for example café) caused a database error: in the Get Relevant tool, when any consumer was saved, and in drush updatedb at post-update 0008. An item whose stored UUID is not in the lower-case 8-4-4-4-12 form (possible after a default_content or migrate import) is no longer matched by include lists.

No post-merge steps. No API or hook change.

Issue #3586742: A detached "Same as parent" subcontext stays published in its other translations.

When a subcontext item that uses its parent's scope is detached, because its parent is deleted or because it is saved while "Enable subcontext hierarchy" is off, every published translation is now unpublished, and a pending Publish on date is cleared. Before, only one translation was unpublished, and the others could reach users outside the parent's scope through the List tool and Broad selections. On moderated sites each other translation is saved in its own revision, so content moderation records it as Archived. A draft save on a published item keeps the editor's text in the latest revision. When the workflow has no unpublished default-revision state, the item stays published and an error is logged. When a draft is saved and the published revision has a scope of its own, the published revision stays published and the draft stays pending.

No post-merge steps. Items that were detached before this change are not changed; check translated items that have no scope and no parent. No API or hook changes: the two new methods on AiContextItem are internal.

Issue #3586746: Site Section patterns do not match paths that have a language prefix.

Site Section patterns now match pages that have a language URL prefix (for example /af/about/team for /about/*). Patterns that include the prefix still work.

Issue #3586747: Fix the docs errors from the 1.0.0-rc2 smoke test before 1.0.0.

None. Documentation only. The 1.0.0 release notes list the known issues from docs/known-issues.md separately, in #3586602.

Issue #3586760: Add a token name to a context item, so its text is available as a Drupal token.

Context items have a new optional Token name field. Administrators can set it in the "Token" section of the item form. When an item has the token name brand_voice, the token [ai_context:item:brand_voice] gives the published content of the item and of its required subcontext children that the current user can view, for example in an AI agent system prompt. Otherwise the token gives an empty value. The scope rules, including Roles, do not apply to the token, and the token works in every token field, not only in AI prompts. A warning shows when a token name changes or is removed, and when a change makes the token empty in a language: an unpublish in the item form or the Content Moderation form, a delete, a revert, or a Scheduler Unpublish on date. The token neutralizer now also breaks an open [ at the end of the pushed context block and of tool outputs. Run drush updb, then drush cr: the update adds the field, and the item delete form, the translation delete form and the token hooks are new.

Issue #3586762: Main menu item title help text loses the "<" character on Drupal CMS.

None. Only a help text and an error message changed.

Issue #3586764: The ai_context_usage view is missing the table CSS class option, which is deprecated in Drupal 11.2.

None. The shipped ai_context_usage view now has the table CSS class option that Drupal 11.2 expects, so installing CCC no longer triggers a deprecation. On Drupal 10 the option is declared in the config schema and has no effect. Existing sites already get the option from core's views update; no steps are needed.
